### Создание процессов и взаимодействие через каналы

ФИО: <u>Морхов Захар Александрович</u>
Группа: <u>М80-201БВ-25</u>
Вариант: 12

### Цель работы

Получить практические навыки создания и управления дочерними процессами,
организации обмена данными между процессами через неименованные каналы,
перенаправления стандартных потоков ввода-вывода и управления системными
дескрипторами в операционной системе Windows.

### Постановка задачи

Разработать программу на языке Си для Windows. Родительский процесс
должен создать два дочерних процесса и организовать последовательную
обработку введённых пользователем строк.

Первый дочерний процесс переводит символы строки в верхний регистр.
Затем строка передаётся второму дочернему процессу, который заменяет
каждую последовательность из нескольких подряд идущих обычных пробелов
одним пробелом. После обработки результат возвращается родительскому
процессу и выводится на экран.

Для взаимодействия используются неименованные каналы (pipes). Дочерние
процессы реализуются как отдельные исполняемые программы. Необходимо
закрывать неиспользуемые дескрипторы и корректно завершать дочерние
процессы.

### Алгоритм решения

1.  Родительский процесс создаёт три неименованных канала:
    -   `inputPipe` - передача исходных строк от родителя первому
        дочернему процессу;
    -   `middlePipe` - передача результата первого дочернего процесса
        второму;
    -   `outputPipe` - передача окончательного результата от второго
        дочернего процесса родителю.
2.  С помощью `CreatePipe` создаются каналы. Каждый канал предоставляет
    дескриптор для чтения и дескриптор для записи. Дескрипторы, которые
    не должны наследоваться дочерними процессами, помечаются с помощью
    `SetHandleInformation`.
3.  С помощью `STARTUPINFOA` настраиваются стандартные потоки дочерних
    процессов. Для первого процесса стандартный ввод связывается с
    читающим концом `inputPipe`, а стандартный вывод - с записывающим
    концом `middlePipe`. Для второго процесса стандартный ввод
    связывается с читающим концом `middlePipe`, а стандартный вывод -
    с записывающим концом `outputPipe`.
4.  Родитель запускает программы `child1.exe` и `child2.exe` при помощи
    `CreateProcessA`. После запуска он закрывает свои копии тех
    дескрипторов, которые ему больше не нужны.
5.  Родительский процесс читает строки из консоли. Каждая введённая
    строка передаётся первому процессу через записывающий конец
    `inputPipe`.
6.  Первый дочерний процесс читает строку из стандартного ввода,
    переводит её символы в верхний регистр и записывает результат в
    стандартный вывод. Благодаря перенаправлению стандартного вывода
    данные попадают в `middlePipe`.
7.  Второй дочерний процесс получает строку из `middlePipe`, удаляет
    повторяющиеся подряд обычные пробелы и записывает результат в
    стандартный вывод. Этот вывод перенаправлен в `outputPipe`.
8.  Родительский процесс читает обработанную строку из `outputPipe` и
    выводит её на экран.
9.  При получении команды `exit` родитель передаёт её дочерним процессам
    и завершает ввод. После закрытия каналов дочерние процессы получают
    признак конца ввода и завершаются. Родитель закрывает оставшиеся
    дескрипторы и ожидает завершения дочерних процессов с помощью
    `WaitForSingleObject`.

### Используемые программы и системные функции

Решение состоит из трёх исходных файлов:

-   `parent.c` - создаёт каналы и дочерние процессы, передаёт строки и
    выводит итоговый результат;
-   `child1.c` - переводит символы строки в верхний регистр;
-   `child2.c` - сокращает последовательности повторяющихся обычных
    пробелов до одного пробела.

В Windows используются следующие функции и структуры:

-   `CreatePipe` - создаёт неименованный канал и возвращает
    дескрипторы для чтения и записи;
-   `SetHandleInformation` - задаёт свойства наследования дескриптора;
-   `CreateProcessA` - запускает дочернюю программу в отдельном
    процессе;
-   `STARTUPINFOA` - позволяет задать стандартные потоки дочернего
    процесса;
-   `PROCESS_INFORMATION` - содержит сведения о созданном процессе и
    его основном потоке;
-   `ReadFile` и `WriteFile` - читают данные из канала и записывают
    данные в канал;
-   `CloseHandle` - закрывает дескриптор системного объекта;
-   `WaitForSingleObject` - ожидает завершения дочернего процесса.

Дескриптор (`HANDLE`) - это значение, через которое программа
обращается к системному объекту, например к каналу или процессу. Канал
имеет читающий и записывающий концы. Данные, записанные в один конец,
можно прочитать из другого.

### Ввод и вывод программы

**Ввод:** строки, вводимые пользователем в консоли. Для завершения
работы используется команда `exit`.

**Обработка:** сначала строка переводится в верхний регистр, затем
последовательности из нескольких подряд идущих обычных пробелов
заменяются одним пробелом.

**Вывод:** родительский процесс выводит на экран строку после обработки
обоими дочерними процессами.

Например, при вводе:

``` text
Hello    world!
this   is   a test
exit
```

ожидаемый результат:

``` text
HELLO WORLD!
THIS IS A TEST
```

В данном примере первая программа преобразует буквы в верхний регистр, а
вторая убирает лишние пробелы. Пробелы в начале и в конце строки
отдельно не удаляются: сокращаются только последовательности из
нескольких подряд идущих пробелов. Речь идёт об обычном символе пробела,
а не о любых пробельных символах.

### Сборка и запуск

Команды выполняются в PowerShell из каталога, в котором находятся все
три исходных файла:

``` powershell
gcc parent.c -o parent.exe -mconsole
gcc child1.c -o child1.exe -mconsole
gcc child2.c -o child2.exe -mconsole
```

После успешной сборки все три исполняемых файла должны находиться в
одном каталоге, если `parent.c` запускает дочерние программы по именам
`child1.exe` и `child2.exe`.

Запуск родительской программы:

``` powershell
.\parent.exe
```

Если компоновщик сообщает об ошибке `undefined reference to WinMain`,
следует проверить, что в `parent.c` объявлена функция `main`, а также
использовать флаг `-mconsole` при сборке.

### Особенности реализации

Для передачи данных используются три канала, поскольку обработка
выполняется последовательно: родитель -> первый дочерний процесс -> второй
дочерний процесс -> родитель.

Важно закрывать ненужные копии дескрипторов после создания процессов.
Если процесс сохраняет открытый записывающий конец канала, другой
процесс может не получить признак конца ввода и продолжить ожидать
данные. Поэтому управление временем жизни дескрипторов необходимо для
корректного завершения программы.

В представленной реализации обработка строк выполняется через буферы
фиксированного размера. Поэтому длина одной строки ограничена размером
буфера, несмотря на то что в постановке задачи требуется поддерживать
строки произвольной длины. Для полного выполнения этого требования
необходимо заменить фиксированные буферы динамически расширяемыми
буферами и предусмотреть обработку строк, которые поступают из канала
частями.

Перевод в верхний регистр с использованием стандартной функции `toupper`
корректно ориентирован прежде всего на символы однобайтовой кодировки,
например английские буквы. Для корректной обработки русских букв в UTF-8
потребуется отдельная обработка Unicode.

### Вывод

В ходе лабораторной работы рассмотрен способ организации взаимодействия
между родительским процессом и двумя дочерними процессами в Windows.
Созданы три неименованных канала для последовательной передачи данных, а
стандартные потоки дочерних программ перенаправлены на соответствующие
каналы. Первый дочерний процесс переводит строку в верхний регистр,
второй сокращает повторяющиеся пробелы, после чего результат
возвращается родительскому процессу.

При выполнении работы изучены назначение дескрипторов, создание
процессов с помощью `CreateProcessA`, настройка стандартных потоков
через `STARTUPINFOA`, передача данных функциями `ReadFile` и
`WriteFile`, закрытие системных объектов и ожидание завершения
процессов. Также рассмотрено, почему важно закрывать ненужные концы
каналов. Для полного соответствия требованию о строках произвольной
длины фиксированные буферы следует заменить динамическими.
